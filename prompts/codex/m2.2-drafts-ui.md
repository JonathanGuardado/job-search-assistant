## Task: Show drafted answers on the answers page and job pages

**Milestone:** 2.2
**Read first:** `AGENTS.md`, `docs/conventions.md`, `docs/decisions/0014-drafted-answers.md` (including its amendments), `docs/domain-model.md` (sections `saved_answers`, `answer_drafts`), and `prompts/codex/m2.1-answers-ui.md` (the page this task extends)

### Goal

The system now drafts answers to application questions in the background: from the owner's profile, from their confirmed career items, and, for "why us?" questions, from each job's posting. Nothing drafted is used until the owner accepts it. After this task the owner sees each draft where the question is asked, on `/answers` and on each job page. They see what the draft is based on, edit it if they like, and press "Use this draft" to make it their answer. Questions without a draft say why, and questions only the owner may answer say so.

### Implementation notes

**One component for a blocking question's draft**, used on both pages: `DraftOrMarker` (`src/app/answers/_components/DraftOrMarker.tsx`). Props: `question: FormQuestion`, `questionKey: string`, `draft: AnswerDraft | null`, `neverDrafted: NeverDrafted | null`, `back: string`. It renders, in this priority:

1. `neverDrafted` set: one line, by kind:
   - `consent`: "Only you can answer this: it records your own agreement."
   - `demographic`: "Only you can answer this: the assistant never infers how you describe yourself."
   - `no_record`: "Only you can answer this: your profile and career record do not hold it."
2. `draft` with status `drafted`:
   - a heading "Draft", then by `method`: `profile` "Drafted from your profile", `experience` "Drafted from your confirmed career items", `motivation` "Drafted from your career items and this job's posting"
   - "Based on" and a list of `draft.basis.facts`, each as plain text
   - the answer form (below) prefilled with `draft.answer`, posting to `acceptDraftAction` with hidden `draftId`, submit "Use this draft", and the note "You can edit it first."
3. `draft` with status `no_basis`: "No draft: " followed by `draft.reason`.
4. `draft` with status `rejected`: "No draft: the drafts used details your career record does not contain." and a `<details>` with summary "Why" holding `draft.reason`.
5. `draft` null: "Not drafted yet." and a form posting to `draftNowAction` (hidden `questionKey`, `back`) with the button "Draft now".

Never show a rejected draft's text, or a draft's `itemIds`.

**The answer form** (`AnswerForm`). Add two optional props:
- `draftId?: string`: when set, the form posts to `acceptDraftAction` with hidden `draftId`, and its button reads "Use this draft". Otherwise it posts to `saveAnswerAction` as today.
- `jobId?: string`: when set, adds hidden `jobId`, so the answer is saved for that job only.

Field choice, names and prefilling stay as today.

**`/answers`, "Questions blocking your applications".** For an `OpenQuestion` answered by `saved_answer`:
- **`draftsByJob` is empty** (a question answered once for every job): render `DraftOrMarker` with `question.draft`, then the suggestion if any (as today), then the answer form as today. When a draft with status `drafted` is shown, put the plain answer form inside a `<details>` with summary "Write your own answer instead".
- **`draftsByJob` is not empty** (an answer per job): no suggestion and no general answer form. Show the line "This question is answered for each job separately." Then, for each id in `question.jobIds`, in order:
  - "<title> · <companyName>", linking to `/jobs/<id>`
  - `DraftOrMarker` with `draftsByJob.get(id) ?? null` and `neverDrafted: question.neverDrafted`
  - Jobs without an entry show "Not drafted yet." and the same "Draft now" form, once for the question rather than once per job.

  Get the titles from the `Job[]` the page already loads with `jobsToApplyTo`. Pass a `ReadonlyMap<string, string>` of job id → "<title> · <companyName>" to the component.

Questions answered by `details` or `resume` are unchanged.

**`/answers`, "Your saved answers".**
- React key `${questionKey}:${jobId ?? 'all'}`.
- When `jobId` is set, a line "For <title> · <companyName> only". Look up names with `getJobs(db, ids)` for the saved answers' job ids; if a job is not found, show "For one job only".
- When `origin` is `draft`, a badge "From a draft".
- Pass the answer's `jobId` to the edit form, and as a hidden `jobId` to the delete form.

**Job page, "Application readiness"** (`ApplicationReadiness`). Add a `jobId: string` prop. The page passes `jobId`. For each blocker:
1. `DraftOrMarker` with `readiness.drafts.get(answer.questionKey) ?? null` and `neverDrafted(answer.question)`.
2. Then the suggestion and the answer form as today.

When the shown draft has a `jobId`, pass `jobId` to the plain answer form so the owner's own answer is saved for this job only. When the draft is `drafted`, the plain answer form goes inside `<details>` "Write your own answer instead", as on `/answers`.

**Server actions** (`src/app/answers/actions.ts`). Same `back` rules, error redirects and no-`redirect`-in-`try` rule as today.
- `saveAnswerAction`: also read optional `jobId`. An empty value is absent; otherwise it must be a UUID, or redirect with "Check your answer." Pass it in the `SaveAnswerSchema` input.
- `acceptDraftAction` (new): parse `draftId` as a UUID. Build the answer exactly as `saveAnswerAction` does from `kind`, `option` and `text`, with the same "Choose or write an answer." error. Call `acceptDraft(scope, { draftId, answer })`. On success, call `queueQuestionMatch` (ignore its result) and redirect to `back`.
- `deleteAnswerAction`: also read optional `jobId` (empty means absent) and pass it to `deleteSavedAnswer`.
- `draftNowAction` (new): parse `questionKey` as a non-empty string. Call `queueDraftNow(getEnv().REDIS_URL, DEV_USER.id, questionKey)`. On failure, redirect with its error. On success, redirect to `back` with `notice=Drafting started. Refresh in a minute to see the draft.`

**Notices.** `/answers` and `/jobs/[jobId]` read a `notice` search parameter (`z.string().catch('')`). When it is set, show it in a `<p role="status">` next to where `error` is shown.

Forms work without client JavaScript; no `'use client'` components. Follow the existing CSS module styles.
