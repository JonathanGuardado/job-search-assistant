## Task: Build the answers page and show application readiness on jobs

**Milestone:** 2.1
**Read first:** `AGENTS.md`, `docs/conventions.md`, `docs/decisions/0013-assisted-applications-first.md` (including its amendment), `docs/domain-model.md` (sections `application_forms`, `applicant_details`, `saved_answers`, `question_match_runs`)

### Goal

After this task the owner sees, for every job they can apply to, whether the system could fill its application form from what they have given, and which questions stand in the way. A new `/answers` page lets them give their standard details once and answer each blocking question once, starting with the questions that block the most jobs. Where they already answered a differently worded question, the page offers that answer for them to accept. Nothing is sent anywhere in this milestone: this is the groundwork for the system filling forms later.

### Implementation notes

**`/answers`.** `export const dynamic = 'force-dynamic'`. Load, in this order: `canApplyJobs`, then `readinessForJobs` for those jobs, then `openQuestions` of it; and, inside one `withTenant`, `getApplicantDetails` and `listSavedAnswers`. Then call `queueQuestionMatch(getEnv().REDIS_URL, DEV_USER.id)` and ignore its result (suggestions are a convenience; the page must render without Redis).

The page has three sections, in this order:

1. **"Your details"**: a form posting to `saveDetailsAction` with `firstName`, `lastName`, `email` (required), `phone`, `linkedinUrl`, `githubUrl`, `websiteUrl` (optional), prefilled. Note under it: "Used for the standard fields of every application."
2. **"Questions blocking your applications"**: a summary line, "<ready> of <total> jobs you can apply to are ready to send; <blocked> are blocked; <n> have no form the assistant can read yet", counting `readinessForJobs` results (`assessed` with status `ready`; `assessed` with status `blocked`; `unsupported` plus `not_fetched`). Then one block per `OpenQuestion`, in the order given:
   - the label, "Required", and "Blocks <jobIds.length> job(s)"
   - `answeredBy` `details`: "Fill this in Your details above." `resume`: "Upload a resume in the resume library." with a link to `/resumes`.
   - `answeredBy` `saved_answer`: an answer form (below), and when `suggestion` is not null, above it: "You answered a similar question: “<savedLabel>”: <value>" with a button "Use this answer" posting to `acceptSuggestionAction` (hidden `label` = the question's label, `savedQuestionKey`).
   - `description` beneath the label when not null, as plain text.
3. **"Your saved answers"**: every `SavedAnswer`: its label, its answer (text, or the option labels joined with ", "), an edit form (the same answer form, prefilled), and a "Delete" button posting to `deleteAnswerAction` with the `questionKey`.

**The answer form** (a component used on `/answers` and the job page). Choose the field the question offers, the first in this order: `single_select`, `multi_select`, `textarea`, `text`. Hidden `label` (the question's label) and hidden `kind` (`choice` for the two select types, `text` otherwise).
- `single_select`: radio buttons named `option`, one per option label.
- `multi_select`: checkboxes named `option`.
- `textarea`: a textarea named `text`; `text`: a text input named `text`.
- A question whose only fields are `file` or `hidden` gets no form.

Submit "Save answer", posting to `saveAnswerAction`.

**The job page, `/jobs/[jobId]`.** Below the match section and above "Your application", add "Application readiness", using `readinessForJobs(db, DEV_USER.id, [job])`:
- `unsupported`: "This job's site has no application form the assistant can read. You will apply yourself."
- `not_fetched`: "The application form has not been fetched yet."
- `assessed`: "Ready to send" or "Blocked by <n> question(s)"; then every `QuestionAnswer` except those with source `form`: the label, "Required" when required, and:
  - when `value` is set: where it comes from (details "Your details", resume "Resume", profile "Your profile", saved "Your answer"), and the value: text truncated to 200 characters, a file's `label`, or the option labels joined with ", "
  - when `blocker` is `unanswered` or `option_missing`: "Needs your answer" (for `option_missing`: "Your saved answer is not one of this form's options"), then the suggestion if `suggestions.get(questionKey)` has one, then the answer form (or the `/answers` and `/resumes` pointers for details and resume questions, as on `/answers`)
  - optional questions without a value: "Optional, left empty"

**Jobs list.** For the rows on the current page whose tab is `can_apply`, call `readinessForJobs` once for those rows' jobs, and show a "Ready to send" badge on each whose readiness is `assessed` with status `ready`. No other tab calls it.

**`markEligible`** (`src/app/jobs/actions.ts`): after `queueMatchNow`, also call `queueFormFetchNow(getDb(), getEnv().REDIS_URL, jobId)`. If either fails, redirect with that error as today; the override stays saved.

**Server actions** (`src/app/answers/actions.ts`, `'use server'`): `saveDetailsAction`, `saveAnswerAction`, `acceptSuggestionAction`, `deleteAnswerAction`. Each reads a hidden `back` field that must start with `/answers` or `/jobs/` (otherwise `/answers`), and redirects to it, with `error=<message>` appended on a parse failure or a failed `Result`.
- `saveDetailsAction`: empty optional fields become null; parse with `ApplicantDetailsSchema`.
- `saveAnswerAction`: `kind` `choice` → `{ kind: 'choice', labels: form.getAll('option') }`; `kind` `text` → `{ kind: 'text', text }`. Parse `{ label, answer }` with `SaveAnswerSchema`. An empty choice or text is the error "Choose or write an answer."
- After a successful save, accept or delete: call `queueQuestionMatch` and ignore its result.

Never call `redirect` inside a `try` block. Forms work without client JavaScript; no `'use client'` components.

**Style.** Follow `src/app/jobs/jobs.module.css`. Plain CSS modules.
