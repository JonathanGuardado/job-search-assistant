## Task: Build the Greenhouse and Lever adapters, scheduled polling, and raw job capture

**Milestone:** 1.4
**Read first:** `AGENTS.md`, `docs/conventions.md`, `docs/architecture.md` (Modules, Module contract, Background work), `docs/domain-model.md` (sections `job_sources` and `raw_jobs`)

### Goal

After this task, the app polls Greenhouse and Lever job boards on a schedule and stores every posting verbatim in `raw_jobs`. Each adapter can also turn a stored posting into a `NormalizedJob`, as a pure, tested function. Turning raw rows into canonical `jobs` rows is milestone 1.5, which is not part of this task. This task builds the replay log that 1.5 and the eligibility engine depend on, so a wrong value here is worse than a missing one.

export const AdapterKeySchema = z.enum(ADAPTER_KEYS)
export type AdapterKey = z.infer<typeof AdapterKeySchema>

const minorUnits = z.number().int().nonnegative()

/** An unstated salary is its own variant, never zero and never an estimate. */
export const NormalizedSalarySchema = z.discriminatedUnion('source', [
  z.object({ source: z.literal('unknown') }),
  z
    .object({
      source: z.literal('posted'),
      minMinor: minorUnits.nullable(),
      maxMinor: minorUnits.nullable(),
      currency: z.string().regex(/^[A-Z]{3}$/),
    })
    .refine((s) => s.minMinor !== null || s.maxMinor !== null, { message: 'a posted salary needs a bound' })
    .refine((s) => s.minMinor === null || s.maxMinor === null || s.minMinor <= s.maxMinor, {
      message: 'salary minimum exceeds maximum',
    }),
])
export type NormalizedSalary = z.infer<typeof NormalizedSalarySchema>

export const NormalizedJobSchema = z.object({
  externalId: z.string().min(1),
  companyName: z.string().min(1),
  title: z.string().min(1),
  description: z.string(),
  locationPolicy: z.enum(['onsite', 'hybrid', 'remote', 'unknown']),
  locationText: z.string().nullable(),
  locationCountry: z.string().regex(/^[A-Z]{2}$/).nullable(),

  applyUrl: z.url(),

export type FetchResult = { readonly raw: readonly RawJob[]; readonly next: Cursor | null }

**Greenhouse**
- Jobs URL: `https://boards-api.greenhouse.io/v1/boards/${token}/jobs?content=true&pay_transparency=true`. There is a single page: `next` is always `null`, and a non-null cursor is `invalid_input`.
- Envelope schema: `z.object({ jobs: z.array(z.looseObject({ id: z.number().int() })) })`. Each element is stored verbatim as one `RawJob` with `externalId: String(id)`.
- Health URL: `https://boards-api.greenhouse.io/v1/boards/${token}`. A 200 response with `{ name: string }` is ok. A 404 is `{ ok: false, message: 'Board not found' }`. Any other failure is `ok: false` with the `getJson` error message.
- `normalize`. Parse the payload with a loose Zod schema: `id` (int), `title` (non-empty string), `content` (string), `absolute_url` (URL), `location` (`{ name: string }`, nullable and optional), `first_published` (string, nullable and optional). If parsing fails, return `invalid_input`, naming the external id and the first issue path.
  - `companyName`: `source.name`. Never the payload's `company_name`, which is unreliable (one board reports "Stone - Linkedin").
  - `title`: `title.trim()`
  - `description`: `htmlToPlainText(htmlToPlainText(content))`. Greenhouse escapes its HTML (`&lt;div&gt;`), so the first pass unescapes it and the second pass converts it.
  - `locationText`: the trimmed `location.name`, or `null` if it is empty or absent
  - `locationPolicy`: `classifyLocationText(locationText)`, defined below
  - `locationCountry`: always `null`. Free-text locations list several countries.
  - `employmentType`: always `'unknown'`
  - `salary`: always `{ source: 'unknown' }`
  - `applyUrl`: `absolute_url`
  - `postedAt`: `new Date(first_published)` if that is a valid date, otherwise `null`
- `classifyLocationText(text: string | null)`. A private function in `greenhouse.ts`, applying these rules in order:
  1. `null` → `unknown`
  2. matches `/\b(non|not)[\s-]remote\b/i` → `unknown`
  3. matches both `/\bhybrid\b/i` and `/\bremote\b|\bhome[\s-]based\b/i` → `unknown`
  4. hybrid only → `hybrid`
  5. remote or home-based only → `remote`
  6. anything else → `unknown`

  Never infer `onsite` from a city name.

**Lever**
- Jobs URL: `https://api.lever.co/v0/postings/${token}?mode=json&skip=${skip}&limit=100`.
  - The cursor is the decimal `skip`. A `null` cursor means 0, and a cursor that is not `/^\d+$/` is `invalid_input`.
  - `next` is `String(skip + 100)` when the page held exactly 100 postings, otherwise `null`.
- Envelope schema: `z.array(z.looseObject({ id: z.string().min(1) }))`. Each element is stored verbatim with `externalId: id`.
- Health URL: `https://api.lever.co/v0/postings/${token}?mode=json&limit=1`. A 200 response with an array is ok, even if the array is empty. A 404 is `{ ok: false, message: 'Site not found' }`.
- `normalize`. Use a loose Zod schema with these fields:
  - `id` (string)
  - `text` (non-empty string)
  - `descriptionPlain` (string, default `''`)
  - `lists` (array of `{ text: string, content: string }`, default `[]`)
  - `additionalPlain` (string, default `''`)
  - `categories` (`{ location?: string, commitment?: string }`, optional)
  - `workplaceType` (string, optional)
  - `country` (string, nullable and optional)
  - `salaryRange` (`{ min?: number, max?: number, currency?: string, interval?: string }`, nullable and optional)
  - `applyUrl` (URL, optional)
  - `hostedUrl` (URL)
  - `createdAt` (number, optional)

  Map the fields as follows:
  - `companyName`: `source.name`
  - `title`: `text.trim()`
  - `description`: join these parts with `'\n\n'`, keeping only parts that are non-empty after trimming:
    1. `descriptionPlain.trim()`
    2. for each list: `` `${list.text.trim()}\n${htmlToPlainText(`<ul>${list.content}</ul>`)}` ``. Lever sends bare `<li>` elements, and without the wrapper they merge onto one line.
    3. `additionalPlain.trim()`
  - `locationPolicy`: `workplaceType` `'remote'` → `remote`, `'hybrid'` → `hybrid`, `'onsite'` → `onsite`. Anything else, including `'unspecified'` and a missing value, → `unknown`.
  - `locationText`: the trimmed `categories.location`, or `null`
  - `locationCountry`: `country` if it matches `/^[A-Z]{2}$/`, otherwise `null`
  - `employmentType`: `'contractor'` when `categories.commitment` matches `/\bcontract(or)?\b/i` and does not match `/fixed[\s-]term/i`. Every other case is `'unknown'`. "Full-time" does not tell you employee versus contractor.
  - `salary`: `posted` only when all of these hold:
    - `salaryRange` is present
    - `interval === 'per-year-salary'`
    - `currency` matches `/^[A-Z]{3}$/`
    - at least one of `min`/`max` is a finite number ≥ 0
    - `min ≤ max` when both are present

    Otherwise `{ source: 'unknown' }`. Convert to minor units as `Math.round(amount * 10 ** digits)`, where `digits = new Intl.NumberFormat('en', { style: 'currency', currency }).resolvedOptions().maximumFractionDigits`. A result above `Number.MAX_SAFE_INTEGER` makes the salary `unknown`. A bound that is absent stays `null`.
  - `applyUrl`: `applyUrl ?? hostedUrl`
  - `postedAt`: `new Date(createdAt)` when `createdAt` is finite, otherwise `null`

**Polling: `pollSourcePage`**
1. Load the source. If it is missing, return `not_found`. If it is disabled, return `ok` without fetching.
2. Parse `config` with `AdapterConfigSchema`; it is jsonb read back from the database. On failure, mark the source `failing` and return `invalid_input`.
3. Call `getAdapter(adapterKey).fetchPage({ name, config }, payload.cursor, deps.fetcher)`. On error, set `health_status = 'failing'`, `health_message` to the error message and `health_checked_at = now()`, then return the error unchanged.
4. In one transaction:
   - insert every raw job with `contentHash(payload)` and `onConflictDoNothing` on the unique key
   - set `health_status = 'ok'`, `health_message = null`, `health_checked_at = now()`
   - if `next` is non-null, set `cursor = next`; otherwise set `cursor = null` and `last_polled_at = now()`
5. After the commit, if `next` is non-null, call `deps.enqueueNextPage({ sourceId, pollId: payload.pollId, cursor: next })` and return its result. A retry re-fetches the same page and inserts nothing, so this ordering is safe.

**Dispatch: `dispatchSourcePolls`.** For every enabled source whose `last_polled_at` is null or at least `POLL_INTERVAL_MS` before `now`, enqueue `{ sourceId, pollId: `w${windowStart}`, cursor: null }`, where `windowStart = Math.floor(now.getTime() / POLL_INTERVAL_MS) * POLL_INTERVAL_MS`. The key is per source and window, so overlapping dispatches enqueue one job.

**Worker (`src/worker.ts`)**
- Register `sourcePollQueue.work({ connection, concurrency: 1 }, …)`. Pass `fetch` and an `enqueueNextPage` that calls `enqueue(p, sourcePollKey(p))` on a queue opened once at startup, mapping a rejection to `upstream_failed`.
- Register `sourcePollDispatchQueue.work({ connection }, () => dispatchSourcePolls(db, new Date(), enqueue))`.
- At startup, call `upsertJobScheduler('source-poll-dispatch', { every: DISPATCH_EVERY_MS }, { name: 'source-poll-dispatch', data: {} })` on the dispatch queue. BullMQ 5.81 is installed.

**`addSource`**
1. Run the adapter's `health`. If it is not ok, return `invalid_input` with the health message and insert nothing.
2. Insert the source with `health_status = 'ok'` and `health_checked_at` set.
3. A unique violation on `(adapter_key, token)` returns `conflict`. Check for an existing row first; do not rely on catching the error, because that aborts the caller's transaction.

**`checkNormalization`.** Read every `raw_jobs` row joined to its source and run the adapter's `normalize`. Collect each failure as `{ sourceId, externalId, message }`. The function is read-only.

**Admin page (`/sources`)**
- A table of `listSources` with these columns: name, adapter, token, enabled, health (badge plus message), last polled, and raw job count.
- Per-row buttons: "Poll now", which enqueues `{ sourceId, pollId: `m${Date.now()}`, cursor: null }` via `enqueueSourcePoll`, and "Enable"/"Disable".
- An add form with an adapter select, a name, and a token. It parses with `NewSourceSchema` and calls `addSource(getDb(), input, fetch)`.
- Errors redirect with `?error=`, as `/resumes` does.
